# FileScope 演示与学习记录

## 一分钟项目介绍

FileScope 是一个本地重复文件管理工具。Python 遍历文件，通过大小筛选、SHA-256 和实际内容比较识别重复；SQLite 保存扫描历史和文件记录；Flask 接收网页请求，Jinja 模板展示报告。用户可主动隔离副本并恢复，操作前重新检查当前文件，恢复时拒绝覆盖已有文件。

参考 fdupes 的检测流程和 dupeGuru 的核心、展示分离思路，保留已有实现逐步扩展，不是对某个 GitHub 项目的逐项复现。当前定位为本机学习与演示版本。

## 五分钟演示流程

1. 启动服务，打开 `/history`，展示已有扫描记录。
2. 输入 `test_data`，发起一次新扫描，进入详情页。
3. 展示文件数量、大小、重复分组和理论可释放空间，解释同大小不代表同内容。
4. 对一个副本点击隔离，展示原路径、隔离路径、保留文件及操作状态。
5. 恢复副本，展示“已恢复”状态，解释不覆盖已有同名文件。

2026-10-13 用户提供截图：扫描 6 显示 7 个文件、161 字节、2 个重复组、理论可释放 62 字节；操作 2 将 `documents/report.txt` 隔离，保留 `backup/report_backup.txt`，随后显示恢复成功。截图提供了网页流程的演示证据，不等于验证了所有异常或生产环境。

展示时说明：62 字节是假设每组保留一份的内容大小估算；隔离仅移动路径，不释放磁盘空间。扫描记录是历史快照，隔离后不会自动改写原报告。只使用测试数据，结束时恢复本次隔离的文件。

## 技术栈如何连接

扫描：网页表单 → `app.py` → `services.scan_and_save` → 扫描器 → 数据库 → 返回扫描编号。

报告：网页请求 → Python 查询 SQLite → 整理重复分组 → Jinja 生成 HTML → 浏览器显示。

操作：网页按钮提交路径 → `app.py` → `quarantine.isolate_file` 或 `restore_file` → 检查与移动磁盘文件 → 数据库更新状态。

SQL 是操作数据库的语言；实际数据在 `filescope.db`。浏览器不直接连接 SQLite，也不直接搬动磁盘文件。

## 可以讲清楚的设计理由

- 先按大小分组：不同大小必然不是相同内容，避免为所有文件计算哈希。
- 哈希相同后比较内容：哈希用于筛选候选，内容比较进一步确认。
- 保存历史后仍重新检查：历史记录反映过去，操作时文件可能已修改、删除或替换。
- 核心与展示分离：命令行和网页共用扫描业务，不为每个入口重写检测逻辑。
- 隔离优先于永久删除：保留可恢复流程；文件操作与数据库更新失败时仍需补偿或人工核对。
